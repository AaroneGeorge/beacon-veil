# RFP-021 coverage: 59 hard requirements

One row per hard requirement in `RFP-021-ethereum-state-attestation.md`. The requirement text is abridged. The RFP text governs. F = Functionality, U = Usability, R = Reliability, P = Performance, S = Supportability, VS = Verification Security. Milestones are M0 to M8 of the combined RFP-021 and RFP-022 proposal (the filed issue text governs). M0: delivered baseline, the prototype and gates G1 to G5 (the work exists before the grant, $0). M1: open checks and decisions, reviewed with Logos (staged public verifier measured, outbound anchor spike, proving on the minimum machine). M2: RFP-021 public update path and a testnet instance following Sepolia. M3: RFP-021 complete. M4: RFP-022 inbound and controls. M5: RFP-022 outbound, failsafe and privacy suite. M6: Logos modules, mini-app, testnet release, deployer journey and audit package. M7: audit remediation. M8: operated reference deployment for 12 months. A row with two milestones, such as `M6, M7`, is delivered in the first and closed in the last. "M0" in a row means the work exists before the grant.

States: **measured** means a raw file exists in `evidence/`. **in tree** means the file or test exists in the repository. It is not claimed as passing unless the row cites a gate run or a raw file. **partial** means some of the row is measured or in tree and the rest is planned. **planned** means it is a milestone deliverable that does not exist yet. A figure or test that is still open is described in plain words in its row.
